# Team OS Fork (Harness-Native) — Validation Plan
*Companion to team-os-fork-harness-native.md. Inherits the mainline plan's semantics: F-tests (does the mechanism work — deterministic, CI-able) vs. A-tests (was the design bet true — measured, thresholded). Mainline register rows R1–R17 apply, plus **R18 (added to the shared register at fork creation — it is the fork's own bet, recorded in both plans)**; this plan validates the kernel through the fork vehicle and adds fork-specific assumptions FR1–FR7. Builder-as-subject results are formative (mainline methodology corrections apply in full). The fork's identity claim is binding: loops before doors — recall without initiative is drift, tracked as a failed exit criterion, not a style note.*

---

## 0. What this plan validates (and deliberately doesn't)

**Validates through the fork:** the four kernel theses — cold start (A-C4), production-as-eval (A-A4), pillar-3 transfer (A-P3), plus the fork's own bet (R18: the harness can carry the kernel without distorting it) — and the safety prerequisites that gate real data (C6 deletion, S1 taint-in-hooks, compilation-injection scan).

**Does not validate (mainline scope, out of fork):** tier portability (X-phase), multi-surface projections, Tier-3 pooling/DP, managed-tier trust battery, datum-granular taint, A-Z1, **and Class C / pillar 1 — no representative (agent-answers-for-you) behavior is validated by the fork; a green A-P3 supports pillars 2/3 only (CN-10)**. The fork writes mainline-schema ledgers precisely so its evidence carries into those later gates.

**Standing drift test (runs every phase):** an *absolute initiative floor* — **≥3** accepted **unprompted deliverables per week** (N=3, arbitrary-pending-baseline; **"accepted" = ✓ in L8 AND unedited-or-lightly-edited per L8 edit distance** — the floor is gameable by padding trivial digests, so acceptance quality is the qualifier; noting honestly: the rejected ratio and this floor are *both* gameable, in opposite directions — the plan chose its poison and guards it) (the digest counts once; each recurring compiled deliverable counts), plus the qualitative check "would this output have existed if the user asked nothing this week?" (Deliberately not a ratio: a ratio punishes a user who asks ten good questions and is trivially gamed by never shipping the door.) If unprompted deliverables trend toward zero, the fork has become a memory product with a chat window; stop and re-read the identity claim.
