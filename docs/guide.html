How Team OS works — end to end

A tool for human teams: each person has a proactive agent, and the agents form the connective fabric that carries what the team knows. This guide walks the whole system — what it does, the workflows, the stack, and how it plugs into Claude over MCP.

Overview

What it does

Team OS compiles your recurring work, drafts deliverables before you ask, runs on a schedule, and shares proven skills across the team — every action inspected by a gate and written to an append-only ledger. Nine capabilities, each a building block (the FK labels are the build items):

FK4 · Compiler

Compiles your job

Mines your history into a job graph, profile/voice, and pre-built skills. Injected content is quarantined.

FK5 · Brief

Day One Brief

An unrequested digest + ✓/✗ job draft + first deliverable, to your Slack DM.

FK6 · Loops

Works unasked

Daily digest and recurring drafts on schedule, scored over time; resumes after restarts.

FK2 · Gate

Every action inspected

A hook reads inside each action — command, path, payload — and permits, asks, or blocks.

FK2 · Ledgers

On the record

Hash-chained logs of what ran, why it was permitted, and every write's lineage.

FK6b · Envelope

Earned autonomy

Permissions widen slowly on your ✓ and narrow instantly on a ✗. Reversible, logged.

FK6c · Door

Reach it from Claude

Read your corpus and propose changes from any MCP client. Writes only ever propose.

FK7 · Transfer

Skills compound

A proven skill is promoted through a gate and lifts every teammate's agent.

FK8 · Scout

Finds patterns

Idle-time discovery surfaces recurring work as low-volume proposals.

Architecture

How it works

The spine is one loop: sources → compile → stores → loops → outputs → signals → learning, and back. Every write passes the gate and lands in a hash-chained ledger. Files are the system of record; databases and indexes are derived and rebuildable.

Connection

MCP & the Claude subscription

Team OS ships as one plugin: gate/ledger hooks, schedule templates, and an MCP server — the door. You add the door to Claude as a connector; from then on any Claude session can use its tools. Loops run on your Claude subscription — no API key.

Fig 5 — the door exposes read + propose over MCP. Reads return from the stores; proposes land in the inbox; only the gate processor commits.

Two ways to run on a subscription

Recommended

Local scheduled tasks full trust

Claude Code Desktop (subscription) runs the loops headless on your always-on machine. Hooks fire locally → every action gated and ledgered. Full trust comes from where the hooks run, not who bills the tokens.

No machine

Cloud scheduled tasks reduced trust

Routines on Anthropic's cloud. Hooks don't demonstrably run; only door actions are gated. Scheduled prompts are fenced to door tools only (linter-enforced) and the reduced trust is disclosed.

Credential domains

Connecting Slack (or Gmail, Drive) to Claude does not connect it to Team OS, and vice versa. Team OS's own sources (Plane A) hold their own grants and run on owned inference; Claude-account connectors are a separate world reachable only to Claude sessions. Different owners, different revocation.

Data

Sources, inputs & outputs

Inputs (opt-in)

  • Claude Code footprint — commands → skills, CLAUDE.md → profile, transcripts → L1.
  • Personal cloud sources (Plane A) — Slack, Drive, Gmail; off until toggled; DMs/email a separate opt-in.
  • Reactions — your ✓/✗ on delivered work (authenticated).
  • Weekly pulse — one-question signal.
  • Proposals — from the door or the scout, into the inbox.

Outputs

  • Day One Brief — Slack DM: digest + ✓/✗ job draft + first deliverable.
  • Shadow-draft deliverables — recurring work drafted into the store.
  • Corpus & skills — committed with lineage; promotable to the team.
  • Dashboard / console — the read-only mission-control surfaces.
  • Ledgers — exportable, hash-chained audit trail.

Discipline: real source data never enters the repo — synthetic fixtures only; distill-then-discard (raw ingest deleted after compile); untrusted content supplies values, never plan structure.

In practice

Use cases

Solo operator

Your agent + specialized members (compiler, loops, scout). The Thursday doc drafts itself on Thursday; the morning digest is waiting. A complete product on its own.

Engineer

Richest footprint — commands and transcripts compile cleanly. The code-review skill and weekly cadence run themselves; annoying 20% automated.

Product manager

Synthesis loops, status representation, commitment tracking — the recurring 60%. Status-update and meeting-summary drafts arrive done.

Cross-person team

A skill one person proves out is promoted and lifts everyone's agent. Organizational memory survives turnover — the fabric compounds.
