Where UI helps most (if you build five things)

  1. #9 The panic surface — live "what is it doing right now" + a reachable kill switch. The one thing a frightened user needs; today CLI-only.
  2. #4–5 The delivery moment — the draft arrives with an inline ✓/✗ and a "why did you make this" provenance peek. Highest frequency; drives every downstream signal.
  3. #7 The envelope dial — autonomy per category, why it moved, the trajectory. Makes "earned autonomy" legible instead of a hidden number.
  4. #13 The proposal inbox — pending schedules/skills with a diff preview, approve/reject. The human-approval step made visible.
  5. #1 Guided install + hook-diff review — today each user hand-reviews ~190 lines of Python; fatal for non-technical adopters.

Highest frequency, and where the acceptance signal — the metric the whole thesis rides on — is born.

Anti-requirements — UI that would be wrong to build

  • A per-person leaderboard. Ranked people/agents by acceptance or quality violates the no-individuation invariant. The temptation lives at #14 — keep it per-skill.
  • The full operator console (§16). On the do-not-build list. The incident controls belong in the CLI (and, minimally, the delivery surface), not a bespoke mission-control.
  • Any output surface beyond Slack DM. Multi-surface projection and phone Door 2 are mainline-deferred.
  • A marketing dashboard shipped before the clocks run. Interface before initiative is the exact inversion the spec forbids.
