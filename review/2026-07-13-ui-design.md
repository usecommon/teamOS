# Team OS Fork — UI Design

- **Date:** 2026-07-13
- **Author:** Claude Fable 5
- **Basis:** Source exploration of all 5 HTML surfaces + the delivery/acceptance/control code paths (`day_one_brief`, `door`, `l8_capture`, `gate_processor`, `circuit_breaker`, `envelope`, `deletion`, `transfer`, `dashboard`, `teamos`).

---

## Design principle (from CLAUDE.md, non-negotiable)

**The harness is the runtime; initiative before interface.** This product needs *few* bespoke UIs. Its interfaces are mostly **messages and controls**, not dashboards. The sanctioned delivery surface is **Slack DM** (multi-surface projection is out of scope); the sanctioned approval surface is **PR + CI**; the operator surface is the **CLI** (the operator console §16 is on the do-not-build list). Any UI that ranks people is an *anti-requirement* (no individuation).

So "what UIs are needed" resolves to a small, ranked set. Below, each surface names its one job, the actions it exposes, the invariant it must hold, its current state in the repo, and the concrete build.

---

## The needed surfaces, ranked by how load-bearing they are

### 1. Delivery surface — where finished work arrives · **Slack DM**
- **Job:** deliver the draft/brief/proposal "done." The message *is* the UI; it carries a link to the deliverable file, not the body.
- **Actions:** read; tap ✓/✗ (see #2).
- **Invariant:** one output surface (Slack DM); send goes through the FK2 gate; no plan structure from untrusted content.
- **Current state:** `day_one_brief.deliver()` routes `slack_post_message` through the gate and emits an L2 send-receipt — **but nothing calls it live.** `teamos brief` is stdout dry-run; the DM target in `config/connectors.json` is the placeholder `SET_PRINCIPAL_SLACK_USER_ID`, `enabled:false`.
- **Build:** wire a scheduled `run_if_due → deliver` against a live Slack client; fill the DM target; this is FK6 delivery, gated behind starting the clock — not new UI, a config + cron wire.

### 2. Accept/reject control — the ✓/✗ signal · **Slack reaction**
- **Job:** the single most load-bearing interaction — the acceptance signal that drives the envelope, the initiative floor, and A-A4.
- **Actions:** ✓ = accept, ✗ = reject; a substantive edit of the deliverable is a third signal.
- **Invariant (CN-1):** counted **only** from the principal's authenticated identity; a forged reaction must never widen autonomy.
- **Current state:** `harvest_reactions()` maps ✓/✗ from Slack reactions and HMAC-stamps only the principal's (`day_one_brief.py:185-202`); non-matches recorded `unattributed` and never counted. **Gap A:** no shipped path calls `harvest_reactions` outside tests/sims. **Gap B:** `capture_edit(..., attribution="principal_authenticated")` trusts a caller-supplied `principal_id` and auto-stamps it — latent CN-1 hole (the envelope ignores `edit` records today, so not yet exploitable). **Gap C:** a raw ✓ reaction has no `edit_distance_normalized`, so it registers but doesn't satisfy the envelope's `is_acceptance` — a latent mismatch.
- **Build:** schedule the reaction harvester; derive `principal_user_id` from authenticated connector identity, not a caller constant; make `capture_edit` verify rather than assert attribution.

### 3. Operator / incident controls — the frightened-user surface · **CLI** ✅ *built this session*
- **Job:** the one thing a nervous user needs most — stop it, reset it, undo it, hold a proposal. The review's sharpest UI finding was that these existed only in prose.
- **Actions:** halt (breaker), reset breaker, view/reset envelope, list/approve/process inbox proposals, undo a file, start an erasure, one-screen status.
- **Invariant:** principal-invoked, direct (never the agent through the gate); the state files these write are protected paths the gate can only READ.
- **Current state → now:** every control existed as tested library code with **no operator entry point** (`circuit_breaker.trip/reset`, `envelope.reset`, `gate_processor.approve`, `deletion.request_erasure`, `transfer.restore_version`). **Now wired into `teamos.py`:**
  ```
  teamos status                                   # breaker + envelope + inbox + gate at a glance
  teamos breaker  {status|trip --reason R|reset}  # the kill switch, reachable
  teamos envelope {status|reset --category C}     # the autonomy dial
  teamos inbox    {list|approve ID|process}       # the human-approval step
  teamos undo     --path REL --sha SHA            # git-backed rollback
  teamos erase    --node ID --request ID          # start a real content purge
  ```
  The breaker file the CLI writes is the exact file `gate.py` reads, so the kill switch is reachable **and** live. Trip/reset/reset are ledgered to L2. Covered by 3 new tests; full suite 246 green.
- **Remaining:** these are CLI-reachable, not yet surfaced in any GUI — correct for the fork's CLI-first stage. A future minimal status/kill affordance in the delivery surface (a ✗-to-halt reaction) is the only GUI worth adding, and only after the clocks run.

### 4. Approval surface — gate for plan-structure & protected changes · **PR + CI / CLI**
- **Job:** a human releases schedule/skill proposals and protected-path changes; untrusted content never adds plan structure unconfirmed.
- **Actions:** review the hook diff, approve, process.
- **Invariant:** default-deny; schedule/skill proposals WAIT until a human approval marker exists (`PLAN_STRUCTURE_KINDS`, `gate_processor.py:155-158`); protected paths require PR review (CN-3).
- **Current state:** the approval gate exists in code; `approve()`'s docstring said "called by the principal (CLI/console)" but there was **no command** — proposals would sit pending forever. **Now released** via `teamos inbox approve/process` (#3). Protected-path approval remains GitHub PR review — no bespoke UI needed.

### 5. Transparency / read surface — per-skill only · **static dashboard**
- **Job:** show what fired, lineage, breaker/envelope state, per-skill quality.
- **Actions:** read only.
- **Invariant:** **per-skill, never per-person-comparative.** This is the individuation line.
- **Current state:** `dashboard.py` renders per-skill (safe) and hosts `audit_no_individuation`; `audit_individuation_ci.py` scans **both** `dashboard.py` and `render_dashboard.py` (correcting the 07-11 review, which said CI never pointed at the big file). **Caveat:** the audit inspects *identifiers only* — a per-person surface built from string keys or HTML would pass. `render_dashboard.py` renders per-*AI-agent* stats (acceptance/quality per roster role) — not per-human, but the `console-demo.html` fleet table reads as a leaderboard and should be cut or converted to per-skill.
- **Build:** strengthen the audit to catch string/HTML person-keys; remove the console fleet/leaderboard table.

### 6. Onboarding / install · **doc page + CLI**
- **Job:** one-time setup — install kit, connect sources, set posture, review the hook diff.
- **Invariant:** opt-in sources; disclosed unattended posture.
- **Current state:** `onboarding.html` + `INSTALL.md` exist but **contradict each other and `launch.html`** — API-key required-or-not, test counts (140 vs 149), gate size (190/200/≤300). These are hard onboarding blockers.
- **Build:** single source of truth for those facts; generate the numbers from the repo (test count, gate LOC) rather than hand-writing them.

### 7. Source-eligibility config · **config file + ledgered toggle**
- **Job:** the allowlist (FK3b) and `dm_email` opt-in the tool enforces neutrally.
- **Invariant:** policy the tool respects, never opinion it holds; the toggle is ledgered; `dm_email` gates `eligibility()`.
- **Build:** minimal — a config surface + a ledgered toggle command; enforce `dm_email` at `eligibility()`.

## Anti-requirements — do NOT build

- **Operator console (§16)** — on the do-not-build list. `console-demo.html` builds toward a forbidden surface; its action affordances are inert `<span>`s anyway. Cut it, or demote to a screenshot.
- **Fleet / leaderboard dashboard** — violates no-individuation. Convert to per-skill or remove.
- **Launch marketing site** — the 606-line `launch.html` is interface-before-initiative; freeze it until the clocks run.
- **Phone Door 2, multi-surface projections** — mainline-deferred.
